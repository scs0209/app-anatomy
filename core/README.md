# 코어와 명령줄 도구 — 구현 상태

기준일: 2026-11-14. 계획 Next Steps 6번의 첫 부분이다. **코어와 명령줄 껍데기까지 만들었다.** 사이트 껍데기, 단독 HTML, 갤러리 CI는 아직 없다.

## 구성

| 위치 | 무엇 |
|---|---|
| `core/src/host.rs` | 호스트 경계: 범위 읽기, 진행 보고, 시계, 기한 |
| `core/src/phys.rs` | 물리 항목: ZIP 목록(ZIP64 포함), 필요한 앞부분만 풀기, 링크 대상 |
| `core/src/parsers.rs` | 안쪽 파서: asar 머리말, DEX, Mach-O 머리말(fat, 암호화 표시), 이진 XML |
| `core/src/tree.rs` | 규칙 색인, 파일 종류 판정, 조립기(바이트를 세는 유일한 곳) |
| `core/src/dissect.rs` | 포장 해부기(macOS 앱, APK, IPA)와 런타임 해부기(Electron, Flutter, React Native, 네이티브) |
| `core/src/lib.rs` | 입력 판별, 결과 만들기, 내보내는 함수 |
| `host/` | 로더와 Node용 입력(시제품에서 가져옴) |
| `cli/anatomy.mjs` | 명령줄 도구 |
| `dist/anatomy_core.wasm` | 빌드된 코어 |

결과의 타입은 `schema` 크레이트를 그대로 쓴다. 그래서 코어가 내는 JSON은 스키마와 어긋날 수 없다.

## 쓰는 법

```bash
node cli/anatomy.mjs <입력>
```

입력은 `.app` 폴더, `.app`이 든 ZIP, APK, IPA다. 요약을 출력하고 `<앱 이름>.anatomy.json`을 쓴다.

| 옵션 | 뜻 |
|---|---|
| `--json <파일>` | 결과를 그 파일에 쓴다. `-`이면 표준 출력에 쓰고 파일은 만들지 않는다. 오류도 JSON으로 표준 오류에 낸다 |
| `--out <폴더>` | 결과 파일을 둘 폴더 |
| `--force` | 같은 이름의 파일을 덮어쓴다 |
| `--rules <파일>` | 규칙 파일을 더한다. 여러 번 쓸 수 있다 |
| `--no-builtin-rules` | 내장 규칙과 가져온 규칙을 쓰지 않는다 |
| `--app <이름>` | ZIP 안에 앱이 여럿일 때 하나를 고른다 |
| `--no-hash` | 입력 해시를 계산하지 않는다(`inputSha256`이 null) |

종료 코드: 0 성공, 2 사용법·입출력·규칙 오류, 3 지원하지 않는 입력, 4 해석 실패.

다시 빌드:

```bash
sh core/build-wasm.sh   # 지은 파일에 이 기기의 경로(홈 폴더, 사용자 이름)가 남지 않게 경로를 바꿔 넣고, 남았으면 실패한다
```

## 표본 12개로 확인한 것

- **12개 모두 해석되고, 결과가 스키마 검증과 불변식 검사(`schema/check.py`)를 통과한다.** 부모 = 자식 합, 정렬, 이름 중복 없음, 요약값 일치.
- **정답 초안과의 대조(`samples-answers/tools/compare.py`): 239개 항목 가운데 230개가 같다.** 그중 32개는 결과가 더 넓게 묶여 있어 출처만 비교했다(예: 정답 `androidx/datastore/`, 결과 `AndroidX` = `androidx/` 전체).
- 다른 9개는 모두 코어 쪽이 더 정확하거나 묶는 기준이 달라서 생긴 차이다:
  - `com/facebook`(4건): 정답은 전체를 런타임으로 적었고, 코어는 React Native에 해당하는 접두어(`com/facebook/react/` 등)만 런타임에 넣었다. 정답 쪽에 적어 둔 미해결 문제다.
  - 이름이 줄여진 클래스(3건): "짧은 이름"으로 모으는 기준이 정답 초안과 조금 다르다.
  - `microtime`(1건): 코어는 asar 안의 부분과 `unpacked` 부분을 합쳤다(확정된 처리).
  - `Assets.car`(1건): 앱 확장 안에도 같은 이름의 파일이 있다.
- 런타임은 12개 모두 정답과 같다. NewPipe는 `compose`(감지만)로 나온다.
- Joplin을 폴더로 넣든 ZIP으로 넣든 총량(613,705,107바이트)과 모든 노드의 바이트가 같다. 압축된 크기(`compressedBytes`)는 ZIP 입력에만 있다.
- Maccy의 유니버설 실행 파일이 아키텍처 조각 둘(arm64, x86_64)로 나뉜다. Mattermost Mobile의 `Payload/` 없는 IPA가 경고와 함께 해석된다.
- 가장 무거운 표본(Joplin Android)의 명령줄 실행이 해시 포함 0.55초, Node 프로세스 최대 메모리 116 MB였다.

## 사이트 껍데기를 만든 뒤에 추가로 확인한 것

- 이 코어가 브라우저(Chromium 156)에서 돈다. `site/README.md` 참고.
- 호스트 인터페이스 시험을 이 코어용으로 옮겼다(`host/test.mjs`). 24건이 통과한다. 기한 초과, 읽기 실패, 노드 상한, 결정성이 들어 있다.
- Node와 브라우저의 결과 JSON이 ZIP, APK, IPA에서 바이트까지 같다.
- 압축된 크기: `.wasm` 546 KB → 203 KB, 가장 큰 결과 JSON(Joplin Android) 5.4 MB → 0.29 MB, Standard Notes 4.2 MB → 0.24 MB. 샘플·갤러리 JSON 예산(압축 기준 1 MB) 안이다.

## 알려진 문제와 하지 않은 것

**예산을 넘는 것**

- `.wasm`이 546 KB다. 예산은 500 KB(추정 초기값)다. 스키마 크레이트의 설명 생성용 의존성(`schemars`)과 JSON, plist 처리가 들어 있다. 줄일 여지는 있지만 손대지 않았다.
- 결과 JSON이 큰 표본이 있다: Joplin Android 5.4 MB, Standard Notes 4.2 MB. 전송할 때 압축한다는 결정에 기대고 있다. 압축된 크기는 재지 않았다.

**확정된 표와 다른 곳**

- asar 머리말을 흘려 읽지 않는다. 시제품과 같이 JSON 전체를 메모리에 올린다(확정은 "흘려 읽기로 바꿈").
- plist는 `plist` 크레이트로 읽는다. XML 엔티티 확장 동작은 여전히 확인하지 않았다.
- 문자열 표식 규칙(`string-marker`)을 적용하지 않는다.
- "감지만" 런타임은 Android의 Compose만 있다. 나머지는 표본으로 표식을 확인하지 못해 넣지 않았다(확정대로).
- 중첩 번들 가운데 Watch 앱, APK 안의 `.jar`, 다중 asar, asar 없는 Electron은 따로 다루지 않는다. 일반 파일로 묶인다.
- 중첩 앱과 앱 확장 안의 실행 파일은 앱 확장의 주 실행 파일만 Mach-O로 읽는다. 프레임워크 안의 실행 파일은 아키텍처 조각으로 나누지 않는다.

**임시로 정한 것 (사용자 확정 전)**

- Android에서 Compose를 감지로 보는 기준: `androidx/compose/` 클래스 100개 이상.
- 앱 패키지 접두어: 매니페스트의 패키지 아래에 클래스가 없으면 마디를 하나씩 줄여 본다. Rocket.Chat에서 필요했다(패키지는 `chat.rocket.android`, 클래스는 `chat/rocket/reactnative`). 계획 9.1이 말한 "application과 activity 클래스 이름의 공통 접두어"는 구현하지 않았다.
- 내장 규칙에 널리 알려진 DEX 패키지 접두어 17개를 넣었다(`rules/builtin/builtin.json`). `com/google/`처럼 넓은 접두어는 서로 다른 라이브러리를 한 이름으로 묶는다. 이름과 분류는 내 지식에 근거한다.
- 리소스(`res/`)는 파일 수가 많아 폴더 단위로 접었다.
- 규칙 검증 오류의 문장이 한국어로 나온다. 다른 오류는 영어다. 맞춰야 한다.

**확인하지 못한 것**

- 이름을 바꾼 Electron 엔진, iOS의 Flutter 앱, 암호화된 IPA, ZIP64, 해석 실패 노드. 표본에 없어 실제로 타 보지 못한 경로다.
- 퍼징. 파서에 "깨진 입력에서 패닉하지 않는다"는 작은 시험만 있다.
- 보류 표본. 아직 받지 않았다.
