# 결과 JSON 스키마 (schemaVersion 1)

기준일: 2026-11-14. 계획 Next Steps 3번의 "결과 JSON"과 "노드 종류 열거값"이다. 규칙 파일 스키마와 호스트 인터페이스는 여기에 없다.

계획이 정한 것은 그대로 옮겼다. 계획에 없던 것은 2026-11-14에 사용자가 하나씩 보고 확정했다(끝의 "확정 기록").

## 파일

| 파일 | 무엇 | 손으로 고치는가 |
|---|---|---|
| `src/lib.rs` | **원본.** Rust 타입과 설명 | 고친다 |
| `result.schema.json` | JSON Schema (draft-07) | 생성물 |
| `result.d.ts` | TypeScript 타입 | 생성물 |
| `example-apk.json`, `example-electron.json` | 예시 결과. 숫자는 설명용으로 지어낸 값이다 | 생성물 (`gen-examples.py`) |
| `check.py` | 형식 검증과, 스키마로 표현하지 못하는 규칙의 검사 | 고친다 |
| `gen-ts.py` | JSON Schema에서 TypeScript 타입을 만든다. 외부 도구를 쓰지 않는다 | 고친다 |
| `generate.sh` | 위를 한 번에 다시 만들고 검사한다 | 고친다 |

```bash
./schema/generate.sh
```

CI에서는 이 스크립트를 돌린 뒤 생성물이 커밋된 것과 같은지 본다(계획 Next Steps 3번).

## 최상위

| 필드 | 뜻 |
|---|---|
| `schemaVersion` | 1. 뷰어는 자기보다 큰 값을 만나면 그리지 않는다 |
| `toolVersion`, `rulesVersion` | 스냅샷 비교에서는 뺀다 |
| `inputSha256` | 16진수 64자. 계산 중이면 `null`. 항상 쓰이는 필드다 |
| `input` | 포장 형식, 앱 이름, 앱 식별자, 앱 버전, 근사치 여부 |
| `runtimes[]` | 감지한 런타임. 바이트 큰 순서. 감지된 것이 없으면 `native` 하나 |
| `completeness` | 총량, 미식별, 안쪽을 보지 못한 부분, `overhead`, `shared`, 해석 실패 노드 수 |
| `copies[]` | "벌 요약". ABI나 아키텍처가 둘 이상일 때만 채운다 |
| `warnings[]` | 코드, 영어 문장, 관련 경로 |
| `root` | 논리 트리. `kind`는 `app` |

식별 비율은 필드로 두지 않았다. `1 - unidentifiedBytes / totalBytes`로 뷰어가 계산한다.

## 노드

| 필드 | 있는 곳 | 뜻 |
|---|---|---|
| `kind` | 전부 | 아래 표 |
| `name` | 전부 | 형제끼리 겹치지 않는다. 뿌리부터의 이름 목록이 노드의 주소다(URL에 담는 값) |
| `bytes` | 전부 | 압축을 푼 바이트. 자식이 있으면 자식의 합 |
| `compressedBytes` | ZIP 항목에서 온 노드 | 보조 지표 |
| `origin`, `confidence`, `evidence` | 출처가 있는 노드 | 출처, 확신도, 근거(`kind`와 `detail`) |
| `category`, `ruleId`, `ruleSource` | 규칙에 맞은 노드 | 분류, 규칙 식별자, 규칙 출처 |
| `paths[]` | 선택 | 입력 안의 경로. 부모와 같으면 쓰지 않는다 |
| `fileKind` | 잎 | 실행 코드, 스크립트, 소스맵, WebAssembly, 이미지, 글꼴, 소리·영상, 현지화, 데이터, 기타 |
| `containerType` | `container` | `abi`, `arch`, `nested-app`, `parsed-file`, `opaque` |
| `encrypted` | 선택 | 실행 코드가 암호화됨 |
| `noModuleLayer` | 선택 | 한 덩어리라 모듈 층이 없음 |
| `shortNameRatio` | DEX의 `parsed-file` 묶음 | 이름이 두 글자 이하인 클래스의 비율 |
| `link` | `link` | 가리키는 경로와 입력 밖인지 |
| `failure` | `parse-failed` | 실패한 파서, 오류 코드, 오프셋 |
| `children[]` | 잎이 아닌 노드 | 이름의 UTF-8 바이트 순서 |

값이 없는 선택 필드는 쓰지 않는다. `false`인 표식과 빈 배열도 쓰지 않는다.

### 노드 종류

| `kind` | 층 | 뜻 |
|---|---|---|
| `app` | 1 | 뿌리 |
| `runtime` | 2 | 런타임 |
| `library` | 3 | 라이브러리 단위. 앱 직속의 에셋 묶음과 실행 파일도 이 층이다 |
| `module` | 4 | 라이브러리 안의 파일, DEX 패키지 안의 클래스 |
| `container` | 부모와 같음 | 묶음 |
| `overhead` | 부모와 같음 | 어디에도 속하지 않는 바이트 |
| `shared` | 부모와 같음 | 여러 구성 요소가 함께 쓰는 바이트 |
| `link` | 부모와 같음 | 링크. 0바이트 |
| `parse-failed` | 부모와 같음 | 안쪽 파서가 실패한 덩어리 |

`overflow`("그 외 n개")는 뷰어가 계산하는 것이라 여기에 없다(계획 8.3).

### 출처

`app-code`, `bundled-app-code`, `library`, `runtime`, `asset`, `unidentified`. 화면의 4색(자체 코드, 외부 라이브러리, 런타임, 에셋)과 미식별, 묶음 단위에 대응한다.

## 스키마로 표현하지 못해 `check.py`가 검사하는 규칙

- 자식이 있는 노드의 `bytes`는 자식의 합과 같다.
- 형제의 이름은 겹치지 않고 UTF-8 바이트 순서로 정렬돼 있다.
- `bytes`는 2^53 미만이다(JavaScript의 숫자로 정확히 담기는 범위).
- `containerType`, `link`, `failure`는 각각 해당하는 종류에만 있고, 그 종류에는 반드시 있다.
- `container`, `overhead`, `shared`, `link`, `parse-failed`에는 출처가 없다. `library`와 `module`에는 출처가 있다.
- `link`는 0바이트 잎이다. `overhead`, `shared`, `parse-failed`에는 자식이 없다.
- `fileKind`는 잎에만 있다.
- `shortNameRatio`는 `parsed-file` 묶음에만 있다. `opaque` 묶음에는 자식이 없다.
- `completeness`의 값이 트리에서 센 값과 같다. `copies`가 트리의 `abi`·`arch` 묶음과 같다.
- `runtimes`는 바이트 큰 순서이고 비어 있지 않다.

## 확인한 것

- 예시 두 개가 JSON Schema 검증과 위 규칙을 통과한다.
- 예시를 Rust 타입으로 읽고 다시 쓰면 같은 값이 나온다(선택 필드 생략 규칙 포함).
- 모르는 필드가 있으면 Rust 타입과 JSON Schema가 모두 거부한다.
- 일부러 틀리게 만든 파일 세 개(합이 안 맞음, 모르는 필드, 정렬 안 됨)를 `check.py`가 잡는다.

## 확인하지 못한 것

- **`result.d.ts`를 TypeScript 컴파일러로 검사하지 못했다.** 이 맥에 `tsc`가 없다. 정의되지 않은 타입 참조가 없는지와 괄호 균형만 봤다.
- 실제 앱의 결과를 이 형식으로 만들어 보지 않았다. 용량 측정 시제품은 다른(더 짧은) 형식을 쓴다.
- 뷰어가 이 필드만으로 계획 10절의 화면을 다 그릴 수 있는지. 뷰어가 아직 없다.

## 묶음 종류

| `containerType` | 뜻 | 자식 |
|---|---|---|
| `abi` | Android의 ABI 폴더 | 있음 |
| `arch` | fat Mach-O의 아키텍처 조각 | 있음 |
| `nested-app` | 중첩 `.app`, `.appex`, `.xpc`. 이름의 확장자로 구별한다 | 있음 |
| `parsed-file` | 안쪽을 해부한 파일(`app.asar`, DEX 파일들). 그 파일의 `overhead`와 `shared`가 이 아래에 놓인다 | 있음 |
| `opaque` | 안쪽을 열지 않은 묶음(Watch 앱, APK 안의 `.jar` 등) | 없음 |

| 1 | 필드 이름 | 줄이지 않는다. 크기는 전송할 때만 압축한다 |

## 알려진 문제: 크기

예시에서 모듈 노드 하나가 줄 바꿈 없이 약 120바이트다(이름 약 15바이트 포함). 용량 측정 시제품의 짧은 형식은 노드당 약 60바이트였다.

- 추정: 클래스 32,370개인 Joplin Android의 결과가 약 4~5 MB가 된다. 시제품에서는 2.1 MB였다. 직접 만들어 재지는 않았다.
- 계획의 예산은 샘플과 갤러리 1 MB이고, 넘으면 모듈 층을 접는다. 이 형식에서는 접어야 하는 앱이 더 많아진다.
- **확정(2026-11-14, 사용자 결정): 형식은 그대로 두고 전송할 때만 압축한다.** 부모 값 물려받기와 필드 이름 줄이기는 하지 않는다.
  - 사이트의 샘플과 갤러리 JSON은 서버가 압축해서 보낸다. 정적 호스팅이 `.json`을 압축해 주는지는 호스팅을 정할 때 확인한다.
  - 합성 데이터(모듈 노드 3만 개)로 재 보니 3.67 MB가 gzip으로 0.16 MB가 됐다. 이름이 규칙적인 합성 데이터라 실제보다 잘 줄어든 값이다. 실제 결과로 다시 재야 한다.
  - 결과 JSON 크기 예산(1 MB)은 **압축된 전송 크기**를 기준으로 읽는다. 이 해석은 내 것이다. 푼 뒤의 크기에는 따로 상한이 필요하다(뷰어 메모리). 값은 뷰어 시제품에서 정한다.
  - 남는 문제: 압축이 걸리지 않는 곳. 단독 HTML은 JSON을 파일 안에 그대로 담고, 명령줄의 `--json`도 그대로 쓴다. 이 둘은 줄지 않는다. 단독 HTML이 너무 커지면 그때 모듈 층을 접는다.
  - 모듈 층 접기(계획 10.15)는 예산을 넘을 때의 수단으로 그대로 남는다.
