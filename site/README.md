# 사이트 — 구현 상태

기준일: 2026-11-15. 놓기, Worker, 오류 화면에 더해 **3D 분해도와 부품 목록**이 있다. 모양은 `DESIGN.md`("Die on a Board", 어두운 기판 하나)를 따른다. 좁은 화면(900px 이하)은 2D 트리맵으로 보인다. 목록에서 이름으로 찾을 수 있다. 결과를 1200×630 공유 카드 그림으로 저장할 수 있다. 공개 앱 12개의 갤러리가 있고, 새 릴리스를 따라가는 CI가 있다(GitHub에서 돌려 보지는 못했다).

## 구성

| 파일 | 무엇 |
|---|---|
| `index.html` | 페이지. 콘텐츠 보안 정책을 건다(글꼴도 같은 출처만) |
| `style.css` | 디자인 값. `DESIGN.md`의 색, 글자, 귀퉁이 표시 |
| `fonts.css`, `fonts/` | Archivo, JetBrains Mono, Pretendard(가변 글꼴, woff2). 모두 SIL OFL 1.1, 라이선스 전문은 `fonts/LICENSE-*.txt` |
| `vendor/three/` | three.js 0.160.0의 모듈과 쓰는 부가 모듈 15개. MIT, `vendor/three/LICENSE`. 부가 모듈의 `from 'three'`만 상대 경로로 바꿨다 |
| `layout.js` | 두 보기가 같이 쓰는 것: 결과 줄이기(`reduce`), 트리맵 배치(`layoutItems`), 표기 도우미 |
| `viewer.js` | 3D 분해도(`chip`). 넓은 화면에서만 내려받는다 |
| `flat.js` | 좁은 화면용 2D 트리맵(`flat`). three.js를 읽지 않는다 |
| `card.js` | 공유 카드(`drawCard`). 단추를 누를 때만 내려받는다 |
| `main.js` | 놓기, 화면 상태, 오류 화면, 큰 부품 표, 부품 목록, 영어·한국어 문구 |
| `worker.js` | 모듈 Worker. 입력 하나를 해석하고 끝난다 |
| `gallery/` | 공개 앱 12개의 결과 JSON, 손으로 적는 목록 `apps.json`, 만들어지는 요약 `index.json`. 첫 화면의 샘플은 이 중 `joplin.json`이다 |
| `gallery.mjs` | `gallery/index.json`을 다시 만든다(`node site/gallery.mjs`). 잎 노드의 합이 전체와 다르면 멈춘다 |
| `build.mjs` | `site-dist/`에 정적 사이트를 모은다 |

```bash
node site/build.mjs
```

`site-dist/`만 정적 호스팅에 올리면 된다. 외부 주소는 하나도 참조하지 않는다(첫 화면을 띄운 뒤 브라우저의 자원 기록으로 확인: 다른 출처 0건).

| 파일 | 크기(압축 전) |
|---|---|
| `fonts/` (woff2 95개. Pretendard는 글자 범위별 92조각이라 쓰는 조각만 내려받는다) | 3,188 KB |
| `gallery/` (결과 12개. 고른 것만 내려받는다. 가장 큰 것 5.4 MB) | 16.6 MB |
| `vendor/` (three.js) | 729 KB |
| `anatomy_core.wasm` | 546 KB |
| `rules.json` (규칙 650건) | 436 KB |
| 나머지(HTML, CSS, JS) | 약 170 KB |
| 합계 | 21.7 MB |

gzip 크기와 첫 화면이 실제로 내려받는 양은 재지 않았다.

주소에 `?lang=en` 또는 `?lang=ko`를 붙이면 브라우저 언어 설정보다 먼저 따른다.

## 3D 분해도

- 바닥 면적 = 바이트, 높이 = 층(앱, 런타임, 라이브러리, 모듈), 색 = 출처. 카메라는 정사영.
- 아주 작은 부품(전체의 0.018% 미만, 또는 한 부모의 91번째부터)은 "그 외 N개" 한 블록으로 묶는다. 합계는 그대로다.
- 처음에는 덮개가 닫힌 칩. 잠시 뒤 열리고 층이 떨어지며, 넓은 화면에서는 큰 부품 여섯 개에 회로선과 라벨이 붙는다. 움직임 줄이기 설정에서는 열린 상태를 바로 보인다.
- 끌어서 돌리기, 화살표 키, 층 단추, 열기·닫기, 블록에 올리면 이름과 크기.
- 왼쪽 "큰 부품" 표와 아래 목록의 줄에 올리면 칩에서 그 블록이 밝아진다. 같은 이름이 여러 벌이면 표에서는 한 줄로 합친다(×N).
- 해석 중과 오류 화면에서는 이전 칩이 덮개를 닫은 채 남는다.
- WebGL을 못 쓰거나 `viewer.js`를 읽지 못하면 안내 문장만 뜨고 놓기, 표, 목록은 동작한다.
- 새 결과를 그릴 때 이전 WebGL 문맥을 버린다.

## 2D 트리맵 (좁은 화면)

- 900px 이하에서는 3D 대신 2D 트리맵을 그린다. 이때 `viewer.js`와 three.js(729 KB)는 내려받지 않는다(자원 기록으로 확인: 0건).
- 면적 = 바이트, 색 = 출처, 빗금 = 안쪽을 모름. 배치는 3D와 같은 함수를 쓴다. 층은 높이 대신 안쪽으로 나뉜 선으로만 보인다.
- 보기 전용: 돌리기, 층 단추, 열기·닫기가 없다. 블록을 누르면 얼음색 테두리와 함께 아래 한 줄에 이름, 크기, 비율, 출처가 나온다.
- 아래 목록의 줄에 올리거나 초점을 주면 트리맵에서 그 블록에 테두리가 생긴다.
- 해석 중과 오류 화면에서는 이전 트리맵을 흐리게 둔다.
- 창 너비가 900px를 넘나들면 보기를 다시 만든다.
- 2026-11-15에 375px에서 확인: 샘플(Joplin), Mattermost IPA 해석 결과, 블록 누르기, 오류 화면, 가로 넘침 없음. 확인하지 못한 것: 실제 휴대 기기의 터치, 가로로 돌린 화면, 영어.

## 빼 보기 (2026-11-15 추가)

부품을 뺐을 때 크기가 얼마가 되는지 보는 기능이다. **크기만 다시 센다. 빼도 앱이 동작한다는 뜻이 아니다**(무엇이 무엇에 기대는지는 이 도구가 재지 않는다). 화면에도 그렇게 적는다.

- 3D에서 블록을 잡아 끌면 그 블록(과 그 위에 얹힌 것)이 따라온다. 70px 넘게 끌어다 놓으면 빠지고(끄는 동안 "놓으면 빠집니다"가 뜬다), 가까이 놓으면 제자리로 돌아간다. **누르기만 해서는 빠지지 않는다**(처음에는 누르면 빠지게 만들었다가 사용자 요청으로 바꿨다). 빈 기판을 끌면 돌아간다. 블록 위에서 끌면 돌아가지 않는다.
- 왼쪽 "큰 부품" 표의 줄은 눌러서 빼고 되돌린다(여러 벌이면 전부). 끌 수 없는 환경(키보드, 터치, 좁은 화면)을 위한 길이다.
- 왼쪽에 `613.7 MB → 327.4 MB (−47%)`와 뺀 것의 이름, "마지막 것 되돌리기", "모두 되돌리기"가 나온다. 부모와 자식을 같이 뺐으면 부모만 센다.
- 맥을 훑은 결과에서는 "Electron 앱 N개가 한 벌을 같이 쓴다면?" 단추가 나온다. 가장 큰 프레임워크 하나만 남기고 나머지를 뺀다.
- 좁은 화면(2D 트리맵)에서는 블록을 눌러 뺄 수 없다(누르면 이름이 나온다). 위 단추와 표는 동작하고, 빠진 부품은 흐리게 그린다.
- 새 결과를 열거나 화면 너비가 900px 경계를 넘으면 처음으로 돌아간다.
- 2026-11-15에 확인: Joplin에서 Electron Framework를 빼면 613.7 → 327.4 MB(286.3 MB, 47%: 표의 수치와 맞다), 둘을 빼고 하나를 되돌리기, 줄을 다시 눌러 되돌리기. 칩에서 블록을 누르기만 하면 아무 일도 없음, 조금 끌었다 놓으면 돌아옴, 멀리 끌어다 놓으면 빠짐, 모두 되돌리면 제자리로, 빈 곳을 끌면 회전. 이 맥을 훑은 결과에서 Electron 한 벌만 남기면 17.81 → 16.65 GB(−6.5%). 375px에서도 단추가 동작. 콘솔 오류 없음.
- 확인하지 못한 것: 영어 화면, 빠진 상태로 만든 공유 카드. 터치에서는 블록을 잡지 않는다(돌리기와 화면 넘기기가 먼저다).
- 한계: 칩의 판에 찍힌 이름과 수치(예: "Electron 562.6 MB 92%")는 빼도 그대로다. 공유 카드의 글은 빠진 것을 반영하지 않는다. APK의 "내 기기용 한 벌만 남기면"은 아직 없다.

## 이 맥 훑기 (2026-11-15 추가)

경쟁 조사에서 "파일 하나를 넣는 판별 도구"는 많고 별이 적었고, "내 기기에 설치된 앱 전부를 훑는" 쪽(LibChecker)이 컸다. 그 방향의 첫 걸음이다.

```bash
node cli/scan.mjs
```

- `/Applications`와 `~/Applications`의 앱을 모두 해석해 `this-mac.anatomy-scan.json` 하나를 쓴다(`--system`은 `/System/Applications`도, 폴더를 직접 줄 수도 있다, `--out <파일>`).
- 앱을 실행하지 않는다. 네트워크를 쓰지 않는다. 결과에 홈 폴더 경로는 넣지 않는다. **결과 파일에는 설치된 앱의 이름과 버전이 들어 있다**(`.gitignore`에 `*.anatomy-scan.json`을 넣었다).
- 결과는 한 앱의 결과와 같은 형식이다. 뿌리가 "이 맥"이고 자식이 앱들이다. 아주 작은 부품은 출처별로 묶는다(출처별 바이트는 그대로, 잎의 합 = 전체를 검사한다). 해석하지 못한 앱은 `scan.skipped`에 적고 합계에 넣지 않는다.
- 사이트에 그 파일을 놓으면(또는 파일 선택) 바로 그린다: 제목 "이 맥의 앱 N개", 첫 문장 "Electron이 N벌 깔려 있고 합쳐서 X GB", 런타임별 앱 수와 크기, 칩(맨 아래 "이 맥", 그 위에 앱 판, 그 위에 런타임·라이브러리·모듈), 큰 앱 표, 목록, 찾기, 공유 카드.
- Electron 벌 수는 이름으로 세지 않는다. Electron 런타임마다 그 안의 가장 큰 런타임 라이브러리를 센다(프레임워크 이름을 바꿔 싣는 앱이 있었다).
- 사이트는 이제 이 도구가 만든 결과 JSON(한 앱의 것도)을 놓으면 다시 열어 준다. 결과가 아닌 JSON은 한 문장으로 알린다.
- 2026-11-15에 이 기기에서 확인: 앱 16개, 17.81 GB, 4.9초, 결과 0.2 MB. 사이트에서 1440px(3D)와 375px(트리맵)로 열어 봄. 콘솔 오류 없음.
- 확인하지 못한 것: 앱이 수백 개인 맥, 해석 실패가 섞인 경우의 화면, 권한이 막힌 폴더, 영어 화면, 이 결과로 만든 공유 카드의 모습.
- npm 배포 준비(2026-11-15): 루트에 `package.json`(이름 `app-anatomy`, 0.1.0, 명령 `app-anatomy`), `LICENSE`(Apache-2.0 전문), `NOTICE`(LibChecker-Rules, three.js, 글꼴 표기), `README.md`를 넣었다. `cli/main.mjs`가 `scan`과 한 앱 해석을 한 명령으로 묶는다. `scan --open`은 끝난 뒤 `cli/serve.mjs`로 사이트와 결과를 127.0.0.1의 빈 포트에 띄우고 브라우저를 연다(사이트는 `?open=scan.json`을 보고 그 파일을 연다). 서버는 127.0.0.1에서만 듣고, 다른 호스트 이름으로 온 요청과 사이트 폴더 밖의 경로를 거절한다.
- 묶음: 139개 파일, 3.7 MB(풀면 5.1 MB). 갤러리 결과는 넣지 않는다(그래서 묶음으로 띄운 화면에는 갤러리와 샘플이 없고, 콘솔에 404가 두 줄 찍힌다).
- 확인: `npm pack`으로 묶은 것을 다른 폴더에 풀어 `scan --open`을 돌림 → 훑기, 서버, 화면(영어)까지 동작. 주소 12개에 대한 응답 코드, 폴더 밖 경로 거절, 다른 호스트 이름 거절(403).
- **아직 npm에 올리지 않았다.** `npm publish`는 계정이 있는 사람이 직접 해야 한다. 2026-11-15에 `app-anatomy`라는 이름은 npm에 없었다(레지스트리 404). 이름은 아직 임시 이름이다: 한번 올리면 그 이름·버전은 되돌리기 어렵다.
- 한계: 브라우저만으로는 안 된다(브라우저는 `/Applications`를 읽지 못한다). `npx`로 실제로 돌려 보지는 못했다(올리지 않았으므로). Windows와 Linux에서는 `scan`이 찾을 앱이 없고 브라우저도 자동으로 열리지 않는다. macOS만 된다. 네이티브 앱은 식별 비율이 낮다(이 기기에서 전체 식별 31%). 층 단추에 "모듈"이 두 번 나온다(앱 안의 묶음이 한 층 더 생겨서다).

## 갤러리

- 페이지 맨 아래의 목록. 줄마다 앱 이름과 버전, 플랫폼, 런타임, 압축을 푼 크기, 출처별 바이트 막대(같은 내용을 글로도 붙였다).
- 줄을 누르면 그 결과 JSON을 내려받아 위 기판에 연다. 칩, 큰 부품 표, 목록, 찾기, 공유 카드가 그대로 동작한다. 지금 열린 줄은 얼음색 테두리로 표시한다.
- 들어 있는 것: Joplin, Mattermost Desktop, Standard Notes, AppFlowy, Maccy(macOS) / Rocket.Chat, Joplin, Immich, LocalSend, NewPipe(Android) / UTM, Mattermost(iOS). 모두 2026-11-14에 도구 0.1.0-dev로 해석한 결과다. 표시 이름, 버전, 플랫폼은 `apps.json`에 손으로 적었다(APK는 결과 안의 이름이 파일 이름이기 때문이다).
- 앱을 더하려면: 명령줄 도구로 결과 JSON을 만들어 `gallery/`에 넣고, `apps.json`에 한 줄을 적고, `node site/gallery.mjs`를 돌린다.
- 2026-11-15에 확인: 12줄이 뜨고 샘플 줄이 표시됨. UTM, NewPipe, LocalSend(1440px)와 Immich(375px)를 눌러 열어 봄. 가로 넘침과 콘솔 오류 없음.
- 확인하지 못한 것: 12개 전부 열어 보기(4개만 열었다), 영어 화면, 느린 연결에서 큰 결과(5.4 MB)를 여는 시간.
- 출처와 라이선스(2026-11-15 추가): 줄마다 오른쪽에 라이선스와 소스 저장소 링크(새 탭)가 있고, 연 앱의 머리에 "출처 저장소 · 릴리스 · 라이선스" 한 줄이 붙는다. 목록 아래에 안내 문장이 있다(라이선스는 프로젝트 자신의 것, 앱 안의 부품은 저마다 다름, 파일이 아니라 잰 결과, 이 프로젝트는 이 앱들과 무관).
- 근거는 `gallery/SOURCES.md`에 적었다. 2026-11-15에 GitHub API로 확인: 저장소 12개가 있고 보관 상태가 아님, 각 파일 이름이 해당 릴리스에 올라와 있음, GitHub가 표시하는 라이선스. Joplin은 GitHub가 라이선스를 표시하지 않아 저장소의 LICENSE 파일을 읽었다(AGPL-3.0-or-later, 데스크톱과 모바일 패키지에 별도 LICENSE 없음). Joplin Android의 릴리스는 `laurent22/joplin-android`에 있다.
- 확인하지 않은 것: 링크를 실제로 눌러 열어 보기(주소가 맞는지는 API 응답과 대조했다), GitHub의 "AGPL-3.0", "GPL-3.0" 표기가 "-only"인지 "-or-later"인지, 이 결과를 공개하는 데 대한 법률 검토.
- 앱마다의 주소(2026-11-15 추가): `?app=<이름>`(예: `?app=rocket-chat`. 이름은 `gallery/`의 파일 이름에서 `.json`을 뺀 것). 그 주소로 들어오면 샘플 대신 그 앱이 열린다. 갤러리에서 줄을 누르면 주소가 바뀌고, 뒤로·앞으로가 앱 사이를 오간다. 모르는 이름이면 샘플을 보이고 주소에서 지운다. 탭 제목도 앱 이름으로 바뀐다.
- "링크 복사" 단추: 갤러리 앱과 샘플에서만 나온다. 복사하는 주소에는 `lang`을 넣지 않는다(받는 사람의 언어로 열린다). 클립보드를 쓸 수 없으면 주소를 글로 보여 준다.
- **사용자가 놓은 파일의 결과에는 주소가 없다.** 결과가 이 기기에만 있기 때문이다. 파일을 놓으면 주소의 `app`을 지우고 "링크 복사" 단추도 나오지 않는다. 그 결과를 나누려면 공유 카드나 결과 JSON을 쓴다.
- 2026-11-15에 확인: `?app=rocket-chat`으로 직접 열기, 줄을 눌러 주소가 바뀜, 뒤로 두 번과 앞으로 한 번, 파일을 놓으면 주소가 비워짐, 샘플로 돌아가기, 모르는 이름(`?app=nope&lang=en` → `?lang=en`). 확인하지 못한 것: 실제 클립보드 복사(자동 확인 환경에서는 클립보드가 막혀 주소가 글로 나왔다), 메신저에 붙였을 때의 미리보기.
- 한계: 정적 사이트라 주소마다의 미리보기 그림(메신저·SNS의 링크 카드)이 없다. 어떤 앱 주소든 같은 제목으로 보인다. 앱별 미리보기를 주려면 앱마다 HTML 파일을 만들어야 한다.
- 없는 것: 정렬과 거르기.

### 자동 갱신

- `site/gallery-update.mjs`: 앱마다 가장 높은 버전의 정식 릴리스(초안·시험판 제외)를 찾고, 기록된 버전보다 높으면 파일을 내려받아 명령줄 도구로 해석해 결과 JSON과 `apps.json`(버전, 릴리스 주소, GitHub가 표시하는 라이선스)을 고친다. 어느 릴리스의 어느 파일인지는 `apps.json`의 `releaseRepo`, `tag`, `asset`(정규식)이 정한다.
- 내려받은 파일은 앱마다 새 빈 폴더에 두고, 실행하지 않으며, 끝나면 지운다. 1.5 GB를 넘는 파일은 받지 않는다. 받은 크기가 GitHub의 표시와 다르면 버린다.
- 넣기 전 검사: 해석 성공, 잎의 합 = 전체, 구성 요소가 있음. 런타임이 바뀌었거나 크기가 30% 넘게 변했거나 경고가 있으면 막지 않고 보고서에 적는다. 한 앱이 실패해도 나머지는 계속하고, 실패한 앱은 그대로 둔다(종료 코드 3).
- `--dry-run`(확인만), `--only <이름>`, `--force`(버전이 같아도 다시 해석: 도구나 규칙이 바뀐 뒤), `--report <파일>`.
- `.github/workflows/gallery.yml`: 월요일 03:17 UTC와 수동 실행. 해석기를 그 커밋의 소스로 새로 짓고, 갱신 스크립트와 `gallery.mjs`를 돌리고, `site/gallery/`가 바뀌었으면 **PR을 연다(직접 병합하지 않는다)**. 일부 앱이 실패하면 PR은 열고 실행은 실패로 표시한다. 액션 두 개는 커밋 해시로 고정했다(checkout v7.0.1, setup-node v7.1.0, 2026-11-15에 GitHub API로 확인).
- 필요한 저장소 설정: Settings → Actions → General → "Allow GitHub Actions to create and approve pull requests".
- 2026-11-15에 이 기기에서 확인: `--dry-run`으로 12개 모두 최신 릴리스와 받을 파일을 찾음(전부 "same"). Maccy를 실제로 내려받아 다시 해석 → 기존 결과와 바이트까지 같음. 기록을 2.7.0으로 낮춰 놓고 돌려 2.8.0으로 갱신되는 경로 확인. 없는 이름은 종료 코드 2. 워크플로의 빌드 명령으로 지은 해석기로 Maccy와 NewPipe를 다시 해석 → 기존 결과와 같음. 워크플로 파일의 YAML 문법.
- **확인하지 못한 것: GitHub Actions에서의 실제 실행.** 이 폴더는 아직 git 저장소가 아니다. PR을 여는 단계, 권한, 러너의 Rust 도구, 예약 실행은 돌려 보지 못했다. 큰 앱(200 MB대)을 내려받는 경로와 실패 경로(종료 코드 3)도 실제로 일으켜 보지 않았다.
- 알아 둘 것: 앱이 릴리스 파일 이름의 규칙을 바꾸면 그 앱은 "릴리스를 찾지 못함"으로 실패한다. `apps.json`의 정규식을 고쳐야 한다. Joplin처럼 라이선스를 LICENSE 파일에서 읽은 앱은 갱신될 때마다 보고서에 "다시 읽어 보라"고 적힌다.

## 이름으로 찾기

- "부품 전체" 위의 입력 칸. 이름에 그 글자가 든 부품을 트리 전체에서 찾아 큰 순서로 늘어놓는다. 대소문자를 가리지 않는다. 경로가 아니라 부품 자신의 이름만 본다.
- 줄마다 어디에 든 부품인지(부모 경로)를 같이 쓴다. 200개씩 보이고 "그 외 N개"로 더 본다.
- 칸 옆에 찾은 개수, 크기 합, 비율을 쓴다. 부모와 자식이 같이 걸리면 부모만 더해 겹치지 않게 센다.
- 0건이면 한 문장으로 알린다. 칸을 비우거나 Esc를 누르면 트리로 돌아간다.
- 찾은 줄에 올리면 칩(또는 트리맵)에서 그 블록이 밝아진다. 작아서 "그 외 N개"로 묶인 부품은 그려진 가장 가까운 부모가 밝아진다.
- 칩 자체는 걸러지지 않는다(찾은 부품만 남기거나 나머지를 흐리게 하지 않는다).
- 2026-11-15에 Joplin 샘플로 확인: "onnx" 532건(170.9 MB, 28%), 대문자 "ELECTRON" 15건, ".js" 3,657건, 없는 이름 0건 문장, Esc로 복귀. 1440px와 375px, 한국어. 확인하지 못한 것: 실제 키보드 입력(자동 시험은 값을 넣고 입력 사건을 보냈다), 한글 조합 입력, 영어 화면, 노드가 아주 많은 결과에서의 속도.

## 확인한 것 (앱 내장 브라우저, Chromium 156)

- **실제 코어가 브라우저에서 돈다.** 콘텐츠 보안 정책 아래에서 로드되고 콘솔 오류가 없다.
- **Node와 브라우저가 바이트까지 같은 결과 JSON을 낸다.** ZIP(Maccy), APK(Rocket.Chat), IPA(Mattermost Mobile) 셋의 SHA-256과 길이가 같았다.
- Joplin Android APK(177 MB): 트리가 뜰 때까지 0.19초, 해시까지 0.59초, 코어 메모리 32 MB.
- 저장 단추가 처음에는 꺼져 있다가 해시가 끝나면 켜진다.
- ZIP이 아닌 파일 → 지원하지 않는 형식 오류 화면.
- 앱이 둘 든 ZIP → 앱 목록 → 하나를 누르면 그 앱이 해석된다.
- 시작하자마자 취소하면 이전 결과로 돌아가고 Worker가 남지 않는다.
- 연달아 두 입력을 넣으면 마지막 것만 화면에 반영된다.
- 파일 목록(폴더 입력)으로 넣으면 "근사치" 표지가 붙는다.
- 샘플로 돌아가기.
- 해석 중 네트워크 요청은 사이트 자신의 파일뿐이다.

호스트 인터페이스 시험(`host/test.mjs`)도 실제 코어용으로 옮겼다. Node에서 24건이 모두 통과한다: 해시, 결정성(같은 입력에서 같은 바이트), 폴더와 ZIP의 트리 일치, 링크 대상, 기한 초과, 읽기 실패(처음부터와 도중부터), 노드 상한, 형식 오류, 앱 목록, 이상한 이름의 경로, 잘못된 규칙.

- **실제 끌어다 놓기와 파일 선택 창.** 자동 시험은 페이지 안에서 파일을 받아 해석 함수에 넘겼다. 사람이 파일을 끌어다 놓는 경로, 폴더를 놓는 경로, 여러 파일을 놓는 경로는 직접 해 봐야 한다.
- **Safari와 Firefox.**
- 30초 강제 종료가 실제로 걸리는 경우.
- 접근성(키보드로 끝까지, 화면 낭독기). 터치 기기. 움직임 줄이기 설정을 켠 상태. 영어의 결과 화면과 좁은 화면.
- 탭 전체 메모리.

## 임시로 둔 것 (확정 전)

- 샘플은 Joplin이다(디자인 미리보기가 Joplin으로 확정되어 맞췄다). `main.js`의 `SAMPLE_FILE`로 갤러리의 다른 항목으로 바꿀 수 있다. 계획은 "외부인 5명의 반응이 가장 좋았던 앱"인데 그 시험을 아직 하지 않았다.
- 2D 트리맵은 따로 디자인 검토를 거치지 않았다. 세로로 긴 블록에는 이름을 쓰지 않는다. 트리맵에서 누른 블록이 "큰 부품" 표의 줄과 연결되지 않는다.
- 진행 단계가 "열기 → 구성 분석 → 런타임 감지" 순서로 온다. 런타임 감지가 해부 안에서 일어나기 때문이다. 계획의 순서(열기, 런타임 감지, 구성 분석)와 다르다.
- 목록의 "그 외 n개"는 누르면 200개씩 더 보인다. 계획은 3D에서 "그 안으로 들어감"이고 목록에서는 처음부터 전부 보인다고 했다.
